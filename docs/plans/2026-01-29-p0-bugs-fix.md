## 执行摘要

修复代码审查中发现的 4 个 P0 级别关键 bug，按影响从大到小的顺序修复：

1. **Notion API 2000 字符限制** - 导致所有用户提交失败
2. **生产环境 PII 日志泄露** - 合规风险
3. **AI 响应缺少运行时验证** - 导致运行时崩溃
4. **ThemeScript 空 catch 块** - 静默主题错误

## 设计原则

- **向后兼容**: 所有改动不改变公开 API 签名
- **渐进增强**: 先验证，失败时有降级方案
- **最小侵入**: 只改必要的代码，不重构无关部分
- **保持简单**: 不引入新的依赖或复杂抽象

## 技术决策

### 1. Notion 存储策略
- **决策**: 将对话从 `properties.Conversation` 移到 `children` blocks
- **理由**: Properties 有 2000 字符限制，页面内容无限制
- **权衡**: 查询稍复杂（但我们只写不读）

### 2. 验证策略
- **决策**: 使用 Zod 验证 AI 响应
- **理由**: 运行时类型安全，清晰的错误信息
- **权衡**: 增加很小的运行时开销（可接受）

### 3. 日志策略
- **决策**: 完全移除生产日志，保留错误日志
- **理由**: 合规，无性能影响
- **权衡**: 生产调试稍困难（但可通过错误追踪补充）

## Bug #1: Notion 2000 字符限制

### 问题描述

**位置**: `src/app/actions/waitlist.ts:255-262`

当前代码将整个对话历史作为 JSON 字符串存储在 Notion 的 `rich_text` 属性中：

```typescript
Conversation: {
  rich_text: [{
    text: {
      content: JSON.stringify(data.messages, null, 2), // 💥 轻松超过 2000 字符
    }
  }]
}
```

**影响**:
- 任何有实质性对话的用户提交都会失败
- 用户看到"提交失败"但不知道原因
- 数据丢失

### 解决方案

将对话历史从 `properties` 移动到 `children` (页面内容块)：

```typescript
await notion.pages.create({
  parent: { database_id: process.env.NOTION_DATABASE_ID! },
  properties: {
    Email: { title: [{ text: { content: data.email } }] },
    'Submitted At': { date: { start: new Date().toISOString() } },
    Requirements: {
      rich_text: [{
        text: {
          content: data.confirmedRequirements
            .map((req, i) => `${i + 1}. ${req.summary}`)
            .join('\n\n')
            .slice(0, 2000) // 安全截断
        }
      }]
    },
    'Summary Points Count': { number: data.confirmedRequirements.length },
    Status: { select: { name: 'New' } }
  },
  children: [
    {
      object: 'block',
      type: 'heading_2',
      heading_2: {
        rich_text: [{ text: { content: 'Conversation History' } }]
      }
    },
    {
      object: 'block',
      type: 'code',
      code: {
        rich_text: [{
          text: { content: JSON.stringify(data.messages, null, 2) }
        }],
        language: 'json'
      }
    }
  ]
});
```

**关键点**:
- `properties` 只存摘要（受 2000 字符限制）
- `children` 存完整对话（无限制）
- 使用 Code Block 格式化 JSON，方便在 Notion 中查看

### 验证方法

1. 创建一个包含 10+ 轮对话的测试提交
2. 确认 Notion 页面创建成功
3. 检查页面内容中的对话历史完整性

## Bug #2: PII 日志泄露

### 问题描述

**位置**: `src/app/actions/waitlist.ts:208-214, 224, 226, 274, 276-283`

生产环境中记录用户邮箱和敏感配置信息：

```typescript
console.log('Email:', data.email); // 💥 泄露用户邮箱
console.log('NOTION_DATABASE_ID:', process.env.NOTION_DATABASE_ID); // 💥 泄露配置
console.error('Error stack:', error.stack); // 💥 泄露内部实现
```

**影响**:
- 用户隐私数据被记录到服务器日志
- 可能违反 GDPR/隐私法规
- 调试信息暴露系统架构

### 解决方案

移除所有调试日志，只保留错误消息：

```typescript
export async function submitToNotion(data: NotionSubmission): Promise<void> {
  // ❌ 删除所有这些日志
  // console.log('=== submitToNotion called ===');
  // console.log('Email:', data.email);
  // console.log('Confirmed requirements:', data.confirmedRequirements.length);
  // ...

  try {
    if (!process.env.NOTION_API_KEY) {
      throw new Error('NOTION_API_KEY is not configured');
    }
    if (!process.env.NOTION_DATABASE_ID) {
      throw new Error('NOTION_DATABASE_ID is not configured');
    }

    const notion = new Client({ auth: process.env.NOTION_API_KEY });

    await notion.pages.create({
      // ... 修复后的代码
    });
  } catch (error) {
    // ✅ 只记录错误消息，不记录详细信息
    console.error('Error submitting to Notion:', error instanceof Error ? error.message : 'Unknown error');
    throw new Error(`Failed to submit to Notion: ${error instanceof Error ? error.message : 'Unknown error'}`);
  }
}
```

**清理范围**:
- 删除包含 PII 的日志（邮箱、用户数据）
- 删除配置信息日志（API keys、Database IDs）
- 删除调试流程日志（"created", "calling"）
- 删除详细错误堆栈（保留错误消息）

### 验证方法

1. 搜索代码中所有 `console.log` 和 `console.error`
2. 确认没有敏感信息被记录
3. 测试错误场景，确认错误信息足够定位问题

## Bug #3: AI 响应缺少验证

### 问题描述

**位置**: `src/app/actions/waitlist.ts:136-142, 189-196`

直接解析 AI 返回的 JSON 并断言为类型，没有运行时验证：

```typescript
const responseText = result.response.text();
try {
  const aiResponse: AIResponse = JSON.parse(responseText); // 💥 无验证的类型断言
  return aiResponse;
} catch (parseError) {
  throw new Error('AI response is not valid JSON');
}
```

**影响**:
- AI 返回格式不符时，应用崩溃
- 类型安全假象，运行时不安全
- 难以调试和定位问题

### 解决方案

#### 步骤 1: 创建 Zod Schemas

创建 `src/types/schemas.ts`:

```typescript
import { z } from 'zod';

// UITreeNode schema (递归定义)
const UITreeNodeSchema: z.ZodType<any> = z.lazy(() =>
  z.object({
    type: z.string(),
    props: z.record(z.unknown()).optional(),
    children: z.array(UITreeNodeSchema).optional(),
    key: z.union([z.string(), z.number()]).optional(),
  })
);

// AIResponse schema
export const AIResponseSchema = z.object({
  uiTree: UITreeNodeSchema,
  summaryPoints: z.array(z.string()),
  shouldContinue: z.boolean(),
  selectedOptions: z.array(z.string()).optional(),
  summary: z.string().optional(),
  intentType: z.enum(['refine', 'new', 'unclear']).optional(),
  clarifyQuestion: z.string().optional(),
  requirements: z.array(z.object({
    title: z.string(),
    summary: z.string(),
  })).optional(),
});

// Summarization response schema
export const SummarizationResponseSchema = z.object({
  summary: z.string().min(1, 'Summary cannot be empty'),
});
```

#### 步骤 2: 在 waitlist.ts 中使用

修改 `submitUserMessage`:

```typescript
import { AIResponseSchema, SummarizationResponseSchema } from '@/types/schemas';

// 在 submitUserMessage 中
const responseText = result.response.text();
try {
  const parsed = JSON.parse(responseText);
  const aiResponse = AIResponseSchema.parse(parsed); // ✅ 运行时验证
  return aiResponse;
} catch (error) {
  if (error instanceof z.ZodError) {
    console.error('AI response validation failed:', error.errors);
    throw new Error(`Invalid AI response format: ${error.errors[0].message}`);
  }
  console.error('Failed to parse AI response:', responseText, error);
  throw new Error('AI response is not valid JSON');
}
```

修改 `summarizeRequirement`:

```typescript
const responseText = result.response.text();
try {
  const parsed = JSON.parse(responseText);
  const validated = SummarizationResponseSchema.parse(parsed); // ✅ 验证
  return validated.summary;
} catch (error) {
  if (error instanceof z.ZodError) {
    console.error('Summary validation failed:', error.errors);
  }
  // 保持现有的降级逻辑
  const firstUserMessage = messages.find(m => m.role === 'user');
  return firstUserMessage?.content || '需求总结失败';
}
```

**关键改进**:
- Zod 提供清晰的验证错误信息
- 区分 JSON 解析错误和格式验证错误
- 保留降级方案，不会完全中断流程
- Schema 和 Type 定义在一起，便于维护

### 验证方法

1. 模拟 AI 返回格式错误的响应
2. 确认抛出清晰的验证错误
3. 确认降级逻辑正常工作
4. 测试正常流程不受影响

## Bug #4: ThemeScript 空 catch 块

### 问题描述

**位置**: `src/components/ThemeScript.tsx:12-14`

完全空的 catch 块，静默吞掉所有主题加载错误：

```typescript
try {
  // ... 主题加载逻辑
} catch (_) {
  // no-op  💥 完全静默的错误
}
```

**影响**:
- 主题持久化失败用户无感知
- 无法调试主题相关问题
- 可能隐藏安全错误（cookie 访问权限）

### 解决方案

添加错误日志和降级方案：

```typescript
export default function ThemeScript() {
  return (
    <script
      dangerouslySetInnerHTML={{
        __html: `
(function() {
  try {
    const cookie = document.cookie.split('; ').find((row) => row.startsWith('theme='));
    const value = cookie ? decodeURIComponent(cookie.split('=')[1]) : 'system';
    const systemDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
    const resolved = value === 'system' ? (systemDark ? 'dark' : 'light') : value;
    const root = document.documentElement;
    root.classList.remove('light', 'dark');
    root.classList.add(resolved);
    root.style.colorScheme = resolved;
  } catch (error) {
    // ✅ 添加错误日志
    console.error('Failed to apply theme from cookie:', error);

    // ✅ 添加降级方案：使用系统偏好
    try {
      const systemDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
      const fallbackTheme = systemDark ? 'dark' : 'light';
      document.documentElement.classList.add(fallbackTheme);
      document.documentElement.style.colorScheme = fallbackTheme;
    } catch (fallbackError) {
      // 如果连降级都失败，至少记录
      console.error('Failed to apply fallback theme:', fallbackError);
    }
  }
})();
        `,
      }}
    />
  );
}
```

**改进点**:
- **可见性**: 记录错误到控制台，方便调试
- **健壮性**: 提供降级方案（系统偏好）
- **安全性**: 降级逻辑也有 try-catch 保护
- **用户体验**: 即使 cookie 读取失败，主题仍能正确加载

### 验证方法

1. 测试正常主题加载流程
2. 模拟 cookie 访问失败（隐私模式）
3. 确认降级到系统偏好
4. 检查控制台错误日志
